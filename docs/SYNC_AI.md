# 云同步与真实 AI 部署

本地阅读无需账号。V0.3.0-beta.1 沿用真实 Supabase 云同步，`deepseek-proxy` 已部署，Web / Android 登录鉴权与非收费状态检查通过。未预置任何 DeepSeek API Key。原创短章 Flash 真实推理最小验证通过：完成 1/1 分片，3 句对白全部归属到 2 名人物，0 未知，1 处人工确认重新打开后仍保存。测试结束已清除会话内存密钥；整本书与复杂人物的识别准确率仍待扩展验证，后续收费调用需另行授权。 自建用户仍须配置自己的云项目。

## Supabase

1. 创建你自己的 Supabase 项目，在 SQL 编辑器**按文件名顺序执行 `supabase/migrations/` 下全部 4 个迁移**：`202611020001_reader.sql`、`202611030001_profile_revision.sql`、`202611040001_sync_safety.sql`、`202611040002_harden_ddl_helper.sql`；或使用 Supabase CLI `supabase link --project-ref <ref>` 和 `supabase db push`。已配置旧版数据库的用户只需补执行未应用的新迁移，现有数据会保留。
2. 在 Auth 中启用邮箱登录，配置正式站点 URL、允许的重定向 URL、SMTP 和邮箱确认策略。首次注册后可能需要先点确认邮件。
3. 在阅读器设置中填写项目 HTTPS URL 和 **publishable / anon 公钥**；也可构建时设置 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`。绝不能把 service-role/secret key 放进前端。
4. 在两台设备登录同一个账号，在书籍详情明确勾选云同步，再执行同步。第一次会上传原文件、章节文本及这本书的元数据。没有选择的书不会被上传。

`reader_records` 保存版本化书籍包，包含章节、阅读位置、书签、人物、对白、纠错和任务检查点。初始原文件位于私有 `novel-files/<用户ID>/<书ID>/original.<格式>`；明确删除后恢复采用 `.../restored-<restoredAt>/original.<格式>`，因此旧删除请求不能删除更新一代的恢复文件。客户端兼容旧版路径；数据库和 Storage 均实施 RLS。`reader_profiles` 只保存阅读偏好与分类。原文、AI 输出、人工纠错分别存于包中不同字段、本地不同表。表与备份都有 schema 版本，可在后续迁移。

同步以本地为主：未联网修改保留在 IndexedDB；手动同步、联网/聚焦后的延迟重试及每分钟在线检查时上传。每个云端书籍包有服务端 revision，写入通过 compare-and-swap RPC 拒绝过期版本；三方合并结合上次快照，保留不同设备新增记录，已有记录的删除优先。书籍 tombstone 保留并清除云端正文、对白与书签，防止旧设备误恢复删除项。阅读位置和同项纠错采用修改时间选择，依赖设备时钟一致。失败不会清空本地库。

分类和阅读偏好也使用独立 revision / CAS RPC，防止并发设备直接覆盖整个配置。分类按稳定 ID 合并，改名按修改时间选择，删除标记优先；偏好按字段与上次快照做三方合并，保留不同字段的独立修改。同一字段在两台设备都被主动修改时，本次成功写入的设备选择优先；CAS 竞争会重新读取本机及远端数据，最多尝试四次，仍冲突则保留本地修改并提示稍后重试。同步途中产生的新本地修改会保留旧合并基线，避免将尚未安装的远端记录当成本机删除。

如果用户在已经删除的书籍记录上**明确重新导入同一原文件**，本地导入器会写入新的 `Book.restoredAt`，值严格大于其已知删除时间；普通阅读、改名和旧设备上传不会生成这个标记。只有明确恢复时间比删除时间更新时，才能替代云端 tombstone，并重新上传已删除的原文件。新删除时间不早于已知恢复时间，二者相等时仍按删除处理。重新导入默认仍不上传，需要再次在详情中允许云同步。

本地导入上限保持 80 MiB。云同步额外要求原文件不超过 **50 MiB**，完整书籍数据包（章节、封面、书签、AI 结果等）不超过 **30 MiB UTF-8 JSON**；后者为服务器 40,000,000 字节 JSONB 限制预留格式化空间。两个限制都会在任何原文件上传前检查，超限时明确提示并保留本地阅读，不会因这个大小错误先上传一个没有云端记录的原文件。修改后的书籍和明确恢复也执行相同检查。客户端还会在首次/恢复上传前核对原文件指纹。

每个同步操作固定到开始时的用户 JWT，账号/项目切换后停止本次同步，避免在上传中途把前一账号数据写入新账号。下载后、原文校验后和写入本地事务时再次检查账号状态；取消逐本上传许可后不会继续发送后续保存请求，已经发出的文件请求可能仍会完成。下载包严格校验 ID、类型、章节引用、文字范围及来源信息；原文件下载后重新计算 SHA256、重新解析章节，与云端包原文匹配后才原子写入。本地正在阅读或修改书签时产生的新改动不会被在途下载覆盖。进入另一账号会纯本地恢复其自己的分类/偏好快照或默认配置，前一账号配置保留在独立快照中；这一步不等待登录刷新或云网络。

本地书籍授权与快照按**云项目 origin + 用户 ID**绑定。登录 B 时隐藏 A 所属的书籍视图，保留物理文件与 A 的本地快照；B 明确重新导入同一指纹文件时，先归档 A 的书籍包，再恢复 B 自己的快照或从原文件建立干净副本，默认不上传，也不带入 A 的书签、人物、纠错和阅读位置。切回 A 且同步其已授权云书时，会恢复 A 自己的本地快照后再合并。原文件在本机可共用，账号私有阅读数据分开保存。导入入口必须在处理既有书籍墓碑前调用账号准备回调，避免 B 的导入误恢复 A 的删除记录。

已授权书籍的云端原文件缺失时，客户端先检查服务端文件状态，再使用校验过的本地原文件修复；权限或网络错误不会被当作文件不存在。本机原文件缺失时可从自己的云副本下载校验，保留较新的本机元数据与位置。第三个迁移还保证旧客户端直接更新数据时 revision 仍递增，并拒绝早于明确恢复的删除标记，避免绕过并发保护。

关闭某本书同步只阻止后续上传，已经上传的副本仍保留；在仍启用同步时删除书籍并再次同步，才能传播删除与删除原文件。切换账号不会自动把前一账号小说上传到新账号，新账号需要自己的逐本许可。退出操作仅退出当前设备，不撤销其他设备的刷新会话；退出不会清除本地文件，未登录时仍可读本机当前书籍。共用设备请使用独立系统/浏览器配置。现有 JSON 备份包含当前活动本机书籍包，尚不导出 settings 中其他账号的隐藏快照；导出该账号前请先切回并恢复其本地视图。备份可能含完整私人小说，应由使用者自行保管。

## DeepSeek 代理

Web 使用已登录的 Supabase Edge Function。客户端 API Key **仅在内存中**，不会写入 IndexedDB、localStorage、备份、同步字段或日志；刷新、退出、切换账号或云项目后需要重新输入。原生版本采用相同策略，未实现“记住密钥”的系统钥匙串功能。账号 / 项目 / Key 变化会取消原任务，并在响应和写库边界拒绝旧任务继续保存。

运行：

```sh
supabase secrets set ALLOWED_ORIGINS="https://asahi12-26.github.io,http://localhost:1420,http://127.0.0.1:1420,https://tauri.localhost,http://tauri.localhost,tauri://localhost"
supabase functions deploy deepseek-proxy
```

函数启用平台 JWT 验证，并额外使用 Supabase `getUser` 验证非匿名登录用户。允许来源为精确白名单；Windows/Android 当前使用 HTTPS WebView 源 `https://tauri.localhost`。上述命令包含目前公开 Web 站点的 origin；自行部署请替换为自己的站点 origin（无需路径）。不要设置通配来源。函数只允许固定 `https://api.deepseek.com/models` 与 `/chat/completions`，拒绝任意代理地址；请求体最多 160,000 字节、上游响应最多 131,072 字节，另限制结构化输入、模型、固定系统提示、输出 tokens 和每请求 $0.10 保守估算额度。并发围栏为单个 warm isolate 的保护，不是跨设备账单硬限。

密钥会随明确操作通过 TLS 发送到**你配置的 Supabase 服务端**，然后作为 Authorization 发送到 DeepSeek。函数只在本次调用内使用、不持久化也不打印。部署者仍须确保反向代理/观测系统不记录请求体；客户端内存策略不能阻止用户安装的不可信扩展或受感染终端读取内存。

「检查代理」发送经过登录认证的 `status` 请求，不发送 Key / 小说、不访问 DeepSeek；「测试连接」只查询 `/models`，不生成文本。选择章节后点击「授权并分析」才会调用收费生成接口，发送对白、邻近上下文及已有人物名称。不要在用户尚未授权时自动分析或重试；当前实现没有自动收费重试。暂停在当前片段完成后生效，取消会中止本地 fetch；上游已经处理的请求仍可能产生费用。

2026-11-06 已核对官方模型 `deepseek-flash` 与 `deepseek-v4-pro`。客户端和代理复用同一份模型 / 报价契约，以峰时缓存未命中价格估计：每百万 input/output tokens 分别 $0.30/$1.20 与 $1.32/$3.96，另加 10% 裕量；使用 UTF-8 字节数保守估输入，输出每片段最多 4096 tokens。每次请求发送前先原子保留费用额度，即使网络超时也不自动退回预算。达到任务累计预算停止，不增加新的请求。服务商未来调价仍需更新共享契约，费用提示不是账单保证；使用者应同时在服务商账户限制充值/支出。报价依据：[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。

对白由确定性扫描器创建段落索引和字符范围，模型只能回填已知候选 ID；无法确认、缺少上下文证据或置信度低于 0.75 一律未知。跨章用书籍 ID+规范化名称生成稳定人物 ID；人工纠错单独保留且覆盖未来 AI 结果。可修改人物名称、别名合并和对白归属。当前分析范围为单章；长单条引文（>1800 字符）会跳过，避免不可控任务规模。分片对白、人物和任务检查点原子保存，任务面板显示进度、错误与结果。

应用内可暂停 / 恢复，失败、关闭或重启后的续跑需再次授权，只处理尚未完成的片段，保留此前失败请求的预留费用。重复分析同一章会被拒绝。恢复时核对模型、章节原文、分片及本机预算记录；云端 / 导入检查点缺少本机费用记录时不会直接续发收费请求，可新建任务，已有识别结果保留。
